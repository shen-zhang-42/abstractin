AbstractIn 把 Zotero 原生 PDF 阅读器、阅读讨论、Markdown 笔记和笔记讨论放在同一个阅读流程中。可以阅读单篇文献，也可以将多篇论文或书籍加入同一个工作区，整理讨论并保存为 Zotero 笔记。

支持本地 **Codex、Claude Code、Gemini CLI、Antigravity**，也可以连接学校、机构或其他服务提供的 **API**。本地 CLI 使用已有安装和登录；API 使用用户配置的地址、认证和模型。模型处理由所选服务完成。

## 功能概览

以下说明覆盖 **v0.2.154** 的功能。

| 功能 | 可以做什么 |
|---|---|
| 单篇与多文献阅读 | 从一篇文献开始，随时添加来源；多文献工作区可建在已有 Zotero collection 下。 |
| 可组合面板 | 选择双栏、四面板、四列或独立笔记窗口，拖动调整面板位置和宽度。 |
| 阅读查证 | 按范围搜索文字、读取命中片段，并在需要时读取相关 PDF 页图。 |
| 论文总结与导读 | 按 paper-reading skill 总结论文，或逐张子图讲解方法、绘制过程与结果。 |
| NoteOut 笔记 | Markdown 实时预览、表格、KaTeX、交换图、字体和格式快捷键。 |
| 独立讨论 | 阅读讨论与各份笔记的讨论分别保存；通过 Quote 主动引用选中的内容。 |
| 全书讨论整理 | 按目录筛选新知识点，原样收录已有回答，保留原语言和公式，支持增量续接。 |
| CLI 与 API 接入 | 查找本地 CLI、检查兼容性、发现可用模型，或配置自定义 API。 |

## 开始使用

1. 安装 **Zotero 10**，从 [最新 Release](https://github.com/shen-zhang-42/abstractin/releases/latest) 下载 **`abstractin.xpi`**。
2. 在 Zotero 中选择 **工具 → 插件 → 齿轮菜单 → 从文件安装插件**，选中 XPI；如有提示，重启 Zotero。
3. 配置助手。使用 CLI 时先在本机安装并登录，再通过 **Setup** 或设置中的 **Guided setup** 查找和检查；使用 API 时填写服务地址、密钥和模型，检查后点击 **Enable**。API 接入不需要安装 CLI。
4. 点击 Zotero 顶部的 **AbstractIn 图标**，在带示意图的下拉菜单中选择布局。在文献库中，可先选中文献，再用 **Add selected documents → Start Reading** 开始；添加多篇时会继续打开来源管理，确认工作区名称和归属。
5. 新文献需要确认标题、材料类型和阅读目标。书籍可初始化目录；论文可直接提问，再按需总结或逐图导读。已保存的阅读状态和讨论会在再次打开时恢复。

安装 XPI 后，无需下载源码、运行 Codespace 或安装 Node.js。设置位于 Zotero 原生 **设置 → AbstractIn**，工作区右上角也有全局设置图标。图标悬停显示操作说明。

用户自行用 Dropbox 等工具维护的链接 PDF，仍通过 Zotero 解析真实路径，无需移入 Zotero 的 storage 文件夹。若直接路径暂时不可读，可使用 Zotero 已打开的同一附件快照。原始 PDF 和附件链接保持不变。

## 布局、窗口与文献来源

一个 AbstractIn 入口提供四种预设，菜单中用不同颜色的方框区分原生阅读器和插件面板：

| 布局 | 显示方式 |
|---|---|
| **Read literature** | 文献与阅读讨论并排；首次打开和从四栏切回时使用相同界面。 |
| **Four panels** | 文献、整高笔记、右侧上下排列的阅读讨论与笔记讨论。 |
| **Four columns** | 从左到右为文献、阅读讨论、笔记编辑器、笔记讨论。 |
| **Separate note window** | 文献与阅读讨论留在主窗口，笔记和笔记讨论在独立窗口中一起显示。 |

Zotero 原生阅读器保持原位。其余三个面板可以拖动重排、通过 **Move** 调整停靠位置，或移到独立窗口并重新组合；面板之间的分隔线可拖动。笔记编辑器与笔记讨论默认联动显示、隐藏和移出。**Hide notes / Show notes** 根据当前状态切换，重新显示时恢复之前的位置、大小和浮动布局。另开 Zotero 原生 PDF 阅读窗口不会自动搬走现有讨论或笔记面板。

各面板使用统一的灰色标题栏和图标操作，窄栏会折叠次要操作。全局设置、布局和来源管理位于整个工作区上方。头部跟随原生阅读器工具栏的高度和背景，侧栏宽度受原生阅读区边界约束。

### 单篇文献与多文献工作区

- **只有一篇文献**：笔记默认挂在该文献下，阅读讨论只针对这一篇，不额外建立工作区 collection。
- **添加第二篇及以上**：通过顶部 **Manage sources**，或来源下拉菜单最上方的 **+ Add documents** 添加。确认名称后建立共享工作区；可以在书库根目录或已有 collection 下创建工作区 collection。
- **共享来源**：顶部显示模式图标、竖线和当前来源标题；下拉菜单查看及切换所有来源。阅读区和笔记使用同一组文献，修改来源会同步更新该工作区内各份笔记的关联。
- **保存位置**：多文献笔记和工作区阅读记录保存在对应 collection 中；各篇关联文献的 NoteOut 入口可以链接到同一份笔记。添加 collection 成员不会取消文献原有的其他 collection 归属。
- **多个笔记**：在 **Save** 后使用 **New note** 新建并命名，使用 **Open note** 切换当前文献或工作区的笔记。每份笔记保留自己的正文、草稿和讨论历史。

来源需要在同一个可编辑书库中，并有可读取的 PDF。来源题名只用于标识范围，不能代替原文证据；多篇来源已加入工作区，不代表模型已经读过全部文献。阅读讨论和笔记讨论分别维护历史，只有主动引用的片段才会加入另一边的问题。

## 阅读与提问

### 书籍和论文使用不同的阅读流程

书籍首次初始化只准备目录，不再复制 PDF 或提取整本正文。插件在前 24 页、当前打开位置附近及目录书签位置查找目录，并继续读取发现的目录续页；找不到时请打开实际目录页再重试。PDF 无需任何书签：插件会用目录页码、章标题和页脚印刷页码核实各章起始位置，也支持 PDF 自带的页码标签，以便按当前页自动归类讨论。只读取有限的起始页搜索窗口和各章候选标题页，不扫描全部正文；无法核实的范围不用于自动分组，可手动选择章节。论文确认后可直接提问，总结仍由用户主动发起。

书籍可以从原文初始化目录，并按章节或附录组织讨论。初始化时插件读取识别到的全部目录页（含续页），分批将原文直接提供给 agent，无需 agent 调用本地文件工具。同一行连排的目录会先拆分，OCR 断词和跨行标题按完整文字与页码核对，重复目录条目去重，并保留原文证据。Agent 会将展示标题中的 OCR 断词还原为正常单词；仍有大量单字母碎片时追加标题校对，只允许保留原字母、数字的排版修正。无独立页码的章标题同样支持 OCR 空格修正后的原文证据核验；校验失败会列出实际缺失或被拒的标题及原因。重新初始化沿用匹配章节的原 ID。当前聊天已归属某章时，选区或当前页暂时没有已验证的章节范围也会沿用该章，不再反复询问；已验证的其他章节位置仍可切换归属。PDF 书签匹配兼容 OCR 异常空格，重名书签不用于猜测页码。提取结果会与目录条目核对，漏项自动补查一次；仍不完整时保留已有目录并提示重试，不保存为初始化成功。阅读标题栏或 **More reading actions** 中提供 **Initialize contents / Reinitialize contents**，开始阅读后仍可补做或重做初始化。目录保存成功后，插件自动把未归组或章节已失效的聊天按新目录整理：单章聊天保留原 ID，多章混合聊天按完整问答拆分，已有有效章节归属保持不变。无法确定的内容保留在 Unassigned；可能调用当前 agent 辅助判断章节，使用其额度。原始聊天与引用 ID 保留，并遵守该文档的 note 保存模式。只剩摘要的聊天按整体归组，不重建已不存在的原始问答。扫描件或无法读取的目录需先 OCR。论文围绕阅读目标和主题展开，可以选择原文总结或直接提问。输入框提示会随材料类型变化。

阅读流程使用随插件打包的 `book-reading` 和 `scientific-paper-reading` 技能及其支持资源。无需配置本地技能目录。插件始终读取安装包里的原始技能；为了让本地 CLI 能读取文件，会自动将原样资源解包到插件自己的缓存目录。

### 围绕当前页面查找原文

插件在发送问题时记录当前 Zotero 阅读页面，并尝试读取该页的 PDF 文本。需要核对原文时，查找范围逐步扩大：

**当前页 → 前后各四页 → 当前章节 → 整本文档。**

查找会优先匹配定理、定义等正文标题和附近证明，避免把引用处当成原始陈述。证据不足时可按查询规则扩大到全书，但先在本地进行关键词、编号等文字匹配，再读取命中的相关片段，减少不必要的模型输入。后续问题可沿用前一轮的原文线索。

论文不设固定补查次数；书籍的额外补查轮数按物理 PDF 页数每 100 页向上取整，至少一轮，例如 700 页对应 7 轮。达到限制或无法定位时说明证据缺口，不据此断言原文不存在。

### 三种回答模式

输入框底部的模式菜单提供三种策略，默认使用带天平图标的 **Balanced**。模式选择会保留；Codex 在同一 chat 中切换模式或模型时继续沿用会话，可见历史保持不变。

| 模式 | 行为 |
|---|---|
| **Context only · 仅上下文** | 只解释用户提供的文字、图片和当前对话，不读取或搜索 PDF，也不从保存的笔记补充材料。必要内容缺失时请用户粘贴。 |
| **Balanced · 按需查证** | 能依据已有上下文和知识、不猜测地回答时直接回答；缺少定理陈述、证明或作者观点等必要证据时自动查 PDF。一般知识与原文结论应明确区分。 |
| **Source only · 仅原文** | 回答的事实依据限于查到的原文或用户提供的原文，不补充外部知识。找不到支持段落时说明已查范围内未找到，不直接断言整本书没有。 |

Balanced 中明确要求“去看原文”会直接触发查证，选中的内容只有定理编号等短片段时也会优先查找。其他问题先判断现有证据是否充分；如果助手要求粘贴缺失的原文或报告无法访问 PDF，插件会按检索规则补查原文后继续回答，避免直接把这类拒绝作为最终回答。查证过程不改变所选模式。

Context only 即使问题要求查原文也不会访问 PDF，需要查证时请切换模式。明确要求本轮不读取或搜索文档，也会限制 Balanced 和 Source only 的原文访问；Source only 在这种情况下只能使用已提供的原文。阅读初始化仍会读取文档结构，不受讨论模式限制。

查找范围仍为 **当前页 → 前后各四页 → 当前章节 → 整本文档**。定位失败或文本无法提取时，插件会报告缺口，不应把猜测当作书中的结论。物理 PDF 页码和书上印刷页码分开处理，只有经过核对的位置才生成页面链接。自动查证需要支持原文读取的助手；扫描 PDF 需要 OCR 或用户提供页面图片。

书籍和论文查证都支持读取相关 PDF 页图。插件先在本地匹配图号、图注或相关文字，再提供相关页图；助手也可以请求指定的物理页图，每轮最多 4 页。页图最长边限制为 2000 像素并缓存复用。需要在 Zotero 中打开对应 PDF，并选择支持图片的助手；图片不可用时会明确标记，不能仅凭图注声称看过图片。Context only 和明确禁止读取原文的请求不会自动生成页图。

旧版本的 Knowledge discussion 会对应 Balanced；已有 Source verification 选择保留为 Source only。

### 英语词汇与用法辅导

选中 PDF 文本后，**Ask Codex about this** 保留普通提问；**Explain language**（原 Explain this）直接启用语言辅导，解释选中文字的英语含义、词汇和语法。

询问英语单词的含义、发音、音标、搭配、语法、表达区别或句子是否自然时，自动启用 [`english-vocabulary-tutor`](skills/english-vocabulary-tutor/SKILL.md)。无需切换新的模式。单独发送一个英语单词也可生成学习卡片。

该技能先概览常见词性及对应词义，并列出常用派生词和适用的语法变化（如动词各形式、名词复数和形容词比较级），再按主要词义讲解，提供美式和英式音标、自然表达、口语与书面语例句，并给出简短练习。目标词、派生词及每个同义词和反义词均标注口语、书面语或两者通用的使用倾向。同义词和反义词重点比较当前词义下的语气、搭配、语法及能否替换，用简短对比例句说明；不展开相关词的无关词义，也不递归扩展词汇。针对具体段落的问题优先解释该处用法。按技能要求，这类回答使用英文，不随普通回答的语言设置切换。科学概念与证明问题仍使用原来的阅读流程。

词汇辅导只额外提交当前问题和选中的句子，允许使用一般语言知识，不受文献阅读模式限制；不检索 PDF 或笔记，不重新拼接聊天历史，也不执行文档工具。必要上下文不足时会请用户提供。词汇问题后直接提交英文句子会继续语言反馈，科学问题则回到阅读流程。技能随安装包发布，在同一 Codex 会话中首次需要时提供，插件更新后刷新，不在每次问单词时重复发送；无需配置本地技能目录。

同一 chat 的 Codex 会话在词汇、普通阅读、原文补查及模型或回答模式切换时保持不变。续用会话仍保有 Codex 自己的对话记忆，词汇请求只是不会再次附带历史。临时连接失败会保留会话；原会话确实无法恢复时，会在聊天中明确记录重建提示。替换或删除消息会明确重置相关 Codex 上下文，避免后台继续保留已移除内容。新 chat、恢复或合并的聊天使用相应的新上下文；Summary 和 Don’t save 的会话保存期限仍然适用。

Codex 通过本地 `app-server` 接收增量文字，边生成边显示完整回答，并可续用旧版 `exec` 创建的会话。词卡内容要求不变；停止生成时保留已显示的文字，生成错误不会当作完整回答保存。调试日志记录初始化、会话就绪、请求接受、首段文字和完成时间，便于区分启动等待与生成耗时；不会为此修改全局 Codex 配置或终止其他 Codex 进程。需要支持 `app-server` 的 Codex CLI。

选区的 Explain language 和 Ask 操作优先使用同一 PDF 当前可见的聊天；已有聊天时不另开侧边栏，也不切换到文档最后保存的另一个讨论。没有可见聊天时才打开阅读面板。同一窗口文档和 PDF 标签的不同对象引用复用原面板及输入草稿。

### 快捷问题、图片与公式

- **Quick questions** 与 **Quote** 位于阅读讨论和笔记讨论输入框左上方。快捷问题先填入输入框，修改后再发送；引用片段先预览再插入。窄栏会自动换行或省略显示，悬停可看完整说明。
- 书籍和论文的快捷问题可以分别在设置中编辑。
- 可以选中 PDF 段落发问，也可以附加当前 PDF 页面图片、上传图片或粘贴、拖入图片；图片能力取决于所选助手。
- 输入使用本地打包的 CodeMirror 6 编辑器，支持 `$…$` 行内公式和 `$$…$$` 独立行、多行公式，复用已有 KaTeX 渲染。点击公式、光标进入公式或移到结束标记后会显示可编辑的 LaTeX 源码，移开后恢复公式。编写源码时，公式内容、命令、括号、数字及 `$` / `$$` 分隔符会分别高亮，未写完的公式也会高亮。行内公式与正文按基线对齐。在 `$$…$$` 内按 Enter 换行，发送时保留原始 LaTeX。编辑器负责选区、整句删除、撤销和中文输入法；加载或运行失败时自动恢复原生文本框及独立公式预览。
- 回答支持 Markdown、KaTeX 数学公式、定理和定义等正式结果，以及经过清理的 SVG。直接在问题中说明需要公式、推导或图示即可。命题、定理等跟随所选讨论主题色，面板操作仍保持灰色。
- 可以复制回答及公式的 TeX 内容，也可以停止正在生成的回答。

### 论文总结与逐子图导读

论文的 **Quick questions** 额外提供两个流程：

- **Summarize paper**：按随插件打包的 `scientific-paper-reading` skill 总结研究问题、方法、主要证据、结果和局限，保存为可编辑的论文总结笔记。这是原文总结，与后面的全书／全文献讨论整理不同。
- **Guide through the paper**：从第一张可核实的图开始，按子图逐步说明图如何绘制、用了什么分析、得到了什么结果。按需读取当前图及相关文字，接近下一张图时再加载，不要求先读完全部图文。

每张子图解释后可以继续追问。点击 **Next subfigure**，或回复“下一张”“没有问题”“next”继续；用 **Exit guide** 或输入“退出导读”结束，也可一直完成所有子图。支持流式输出的助手边生成边显示；图片或证据无法核实时会说明缺口，不把图注当作已检查过的图像。

## 会话管理

界面文案统一使用英文；提问、回答和用户自定义内容的语言不受影响。未单独设置过保存方式的文献沿用升级前的默认方式；全新安装默认为 Full。

在每篇文献的聊天输入框下方，通过与思考程度并排的 **Note saving** 图标按钮单独选择保存模式，同一文献下的所有 chat 和 PDF 附件共用；不同文献互不影响。界面选项使用英文：

- **Full**（原样保存）：沿用原来的完整聊天和 Zotero 笔记保存方式。
- **Summary**（摘要保存）：每次回答后由该回答使用的 agent 更新当前会话摘要，合并重复问题，保留结论、公式和未解决的问题；会消耗该 agent 的额度。后续优先提交“已有摘要＋新增消息”，未变化时直接复用，使用较低推理强度以减少等待。窗口中仍显示完整聊天，保存到本地与 Zotero 同步笔记的只有摘要。关闭阅读面板或窗口后重新打开，显示摘要，不恢复完整 CLI 线程。
- **Don’t save**（不保存）：新的聊天内容、CLI 会话和自动阅读笔记只保留在内存，关闭阅读面板或窗口后清空，不生成新聊天文件或同步笔记。

切换模式只处理该文献当前打开的聊天和内存会话，不影响其他文献；此前保存的历史笔记不会批量删除或转换。在摘要模式下，当前会话关闭后只恢复已保存的摘要，不再恢复该会话的全文；未参与转换的旧完整记录仍可切回 Full 查看。若摘要生成失败，界面会提示，完整内容只留在当前窗口中，既有摘要不被覆盖；关闭前可打开该文献的 **Note saving** 菜单，点击 **Retry summary** 重试。


文献条目下的 **NoteIn** 是默认折叠的虚拟笔记分组。插件启动时自动整理已有的 AbstractIn 阅读笔记和聊天记录，新笔记保存后也会自动加入；标题以 `AbstractIn — ` 开头、缺少新元数据的旧插件笔记也会自动整理，无需点击按钮。原有笔记的 ID、内容、文献归属和存储位置不变，用户普通笔记保持原位置。插件只创建一个小型 NoteIn 索引笔记作为分组入口，不创建真实子文件夹；明确标记属于其他文献的笔记不会纳入，只读文库不会创建或更新索引。

展开文献条目，再展开 **NoteIn** 即可查看笔记。未分类条目、标签筛选、文字搜索和保存的搜索中，文献下的插件笔记都支持折叠分组。搜索视图只分组当前结果中的笔记，不补入未命中的笔记；没有父文献行的独立笔记命中和回收站保留 Zotero 原生显示。关闭插件后笔记恢复平铺显示。

### 会话浏览、搜索与恢复位置

右上角的 **Chats** 统一提供会话浏览、管理、搜索和跳转。

初始化输出归入 **Initialization** 分组，默认只有一个会话；再次初始化或更新论文总结会复用这个会话。普通提问和新建讨论不会写入初始化会话。Move discussion 的目标列表包含 Initialization，手动移入的会话独立保留，也可以再移到其他章节。旧版本放在 Unassigned 的初始化轮次会在打开文档时自动整理，普通问答保留在原会话，并保存迁移前的原始备份。

- **按章节展开**：章节标题可折叠，会话分别显示醒目的 `Discussion-01` 编号和主题名称。
- **自动命名**：Codex 根据会话中的问题概括主题；可以手动改名，手动名称会被保留。
- **新建会话**：输入框下方的按钮在当前章节建立独立讨论。
- **恢复浏览位置**：每个 chat 单独记住上次阅读位置，重新打开回到该处；发送问题继续讨论时转到最新内容。
- **跳转到某一轮**：点击会话的 **Turns**，查看问题与回答预览并跳转到对应位置。
- **搜索并跳转**：搜索当前文档或全部文档中的会话名称和消息，点击匹配结果定位。搜索在本地完成。
- **删除和合并**：支持单个或批量删除、多选合并及操作确认；合并后的会话自动概括命名。
- **删除一轮对话**：回答的更多操作菜单中有 **Delete this turn**，一次删除对应的问题和回答。

删除或合并后，会话显示编号与会话内结果编号会重新整理。跨章节合并的讨论归入未分配分组，同章节合并保留章节归属。切换会话会保留未发送的草稿，各会话使用独立的助手线程；删除一轮后会重置线程，避免继续使用已删除内容作为上下文。

会话删除主要作用于历史索引和界面，本地原始记录可能保留用于恢复。独立保存的 Zotero 阅读笔记不会因删除一轮而一并删除。进行中的回答和会话切换会限制冲突操作。

旧版本会话可通过 Chats 中的迁移入口导入，并在确认章节归属后整理。详细行为见 [章节讨论说明](docs/CHAPTER-DISCUSSIONS.md)。

## 全书／全文献讨论整理

阅读标题栏的 **Export reading summary**（窄栏中在 **More reading actions**），或 **Note saving → Summarize all book conversations**，收集当前文献全部章节、全部会话中的已有回答，论文也有对应入口。它整理已有讨论，不重新总结整本书原文。

模型批量判断回答是否提供新的知识点。用户问题只作为分类线索，不单独整理；新知识点收录，重复回答跳过，新例子、更正和实质性补充可以保留。入选正文由插件直接复制，保留原语言、公式和代码，不让模型重写整篇长答案。

知识点按书籍初始化的真实目录章节组织，而不是直接沿用 chat 的章节；无法确定时归入 **Unassigned**。默认分为 **Book content** 和 **Language** 两部分，语言学习或语言研究类书籍可只保留一部分，也可用 **Organization** 指定。

每批完成即预览并保存 `exports/summary-state.json`（决定、来源和进度）及 `exports/reading-summary.md`（可阅读的输出）。未变化部分复用，新增回答增量处理，中断可续接，历史改动后从受影响位置重建。只有旧摘要可用时会标明全文缺失。生成使用助手额度，可另存 Markdown；不修改原有聊天、笔记或 PDF。

## NoteOut：笔记编辑与 AI 讨论

笔记可以和原文一起停靠，也可以与笔记讨论一起移到独立窗口。两种方式共用同一份 Markdown 正文和该笔记的讨论历史。标题和文件操作集中在同一行；**Save、New note、Open note** 使用独立图标，更多操作在 **More** 中。

### 实时预览编辑器

编辑器基于 **CodeMirror 6 与 t-shoot Live Preview**，直接编辑 Markdown，光标所在位置进入源码编辑，其余内容保持渲染。支持标题、加粗、斜体、列表、引用、链接、代码块和表格，表格可直接编辑单元格，也可切换 Markdown 源码。引用块沿用编辑器默认的 Markdown 行为。

Markdown 源码是唯一正文来源。编辑区铺满剩余高度，正文独立滚动，标题和操作栏保持在上方。正文和标题自动保存，也可点击 **Save** 或按 **Ctrl/Cmd+S**；未保存时 Save 为黑色，保存成功后变灰。外部修改发生冲突时保留本机草稿，避免覆盖已有内容；普通 Zotero 笔记不会被自动转换。

点击格式图标打开字体、格式工具和 **?** 快捷键帮助。字体支持 System、Arial、Georgia、Times New Roman、Consolas、Microsoft YaHei 和 SimSun，立即作用于显示，不改写 Markdown。选中文字加粗、斜体或删除线时，边缘空白留在格式标记外。

| 快捷键 | 功能 |
|---|---|
| Ctrl+B / Ctrl+I | 加粗／斜体 |
| Ctrl+Shift+X | 删除线 |
| Ctrl+E / Ctrl+Shift+K | 行内代码／代码块 |
| Ctrl+K | 链接 |
| Ctrl+Alt+1～6 / Ctrl+Alt+0 | 标题／普通段落 |
| Ctrl+Shift+8 / Ctrl+Shift+7 | 无序／有序列表 |
| Ctrl+Shift+L / Ctrl+Shift+9 | 任务列表／引用 |
| Ctrl+S / Ctrl+Z / Ctrl+Y | 保存／撤销／重做 |

macOS 使用 Cmd 对应 Ctrl，Option 对应 Alt，重做为 Cmd+Shift+Z。快捷键暂不支持自定义。

### 公式与交换图

KaTeX 支持 `$…$`、`$$…$$` 公式和简单的 `CD` 交换图。点击公式可编辑 LaTeX，离开后恢复渲染。更复杂的交换图使用本地打包的 TikZJax，在 `tikzcd` 代码块中书写，例如：

```tikzcd
\begin{tikzcd}
A \arrow[r, "f"] \arrow[d, "g"'] & B \arrow[d, "h"] \\
C \arrow[r, "k"'] & D
\end{tikzcd}
```

离开代码块后编译为图，点击 **Edit source** 再编辑。引擎和字体随插件安装，相同图形缓存复用；编译错误或超时会显示提示并保留源码。表格单元格内的公式渲染暂未支持。

### 笔记讨论、引用与修改提案

笔记讨论复用现有模型设置和阅读讨论的输入框样式，提供 **Answer questions** 与 **Edit note**，上下文可选择整篇笔记或 **Use editor selection only**。发送时冻结该版本笔记，后续编辑不会改写已经发送的上下文。

输入框左上方提供 **Quick questions** 与 **Quote**。笔记快捷问题包括总结、解释推理和改进建议。Quote 可以选择本笔记的已有回答，也可以主动浏览关联阅读讨论中的结果；先审阅片段，再插入问题，不自动发送或合并两边历史。

**Edit note** 生成修改预览：点击 **Apply edit** 应用并保存，或点击 **Discard** 放弃。若正文在生成期间发生变化，旧提案不会覆盖新内容。**More → Append last answer** 可将最近回答追加到笔记；可用时，**Use in document discussion** 将选区或全文放入阅读讨论输入框，检查后再发送。

笔记讨论保存在每份笔记的本机工作目录，目前不随 Zotero 笔记正文跨设备同步。模型可以讨论实际提供的笔记和引用片段；关联文献的题名不代表已读取其全文。

### 独立笔记管理与删除

文献库中的 **New Markdown note / Open selected Markdown note** 还可打开带文件列表的 NoteOut 管理窗口：左侧筛选和管理笔记，中间编辑，右侧讨论，两条分隔线可拖动并分别记住宽度。

此管理窗口的 **editor Source** 是笔记列表的来源筛选，每份笔记的 **Source** 是实际文献关联，二者分别维护；列表显示所选来源关联笔记的并集。单篇笔记保存在该文献的 **NoteOut** 下，多篇共享笔记正文在书库中只保留一份，各文献提供链接。停靠阅读工作区则统一使用顶部共享来源，不再维护一套单独的笔记来源。

笔记列表条目悬停时的红色 **×**，或 **More → Move to Trash**，可在确认后将笔记移到 Zotero 回收站。删除当前笔记前保存草稿；关联文献、其他笔记和本机恢复文件保留。共享链接会更新，恢复笔记后重新打开可重建关联。

## 引用已有讨论

两个讨论框左上方的 **Quote** 提供主动引用。阅读讨论中按三级选择：

**章节 → 会话 → 定理、定义、引理或其他结果。**

菜单使用固定标题和图标返回按钮，章节显示讨论数量，会话展示主题，结果分开显示编号、标题与摘要。选择后可审阅和编辑引用片段，再插入当前问题，不会自动发送。笔记讨论中还可选择本笔记已有回答，或主动浏览关联阅读讨论；各自历史保持独立。

会话中的结果使用单独的 **Chat** 前缀和编号样式，例如：

- `Chat Theorem 1.1.1.1`
- `Chat Definition 1.1.1.2`
- `Chat Result 1.1.2.1`

四段编号依次表示 **章节、会话、对话轮次、结果序号**。不同结果类型共用最后一个计数；附录使用相应的附录标识。这些编号与原书的 `Theorem A.78` 等编号区分开，原文编号不被改写。

引用通过稳定的结果 ID 关联。删除或合并导致显示编号变化时，已有引用标签会随之更新。引用的助手结论仍属于讨论内容，不能替代经过核对的原文证据。

## 阅读记录与多设备同步

单篇文献的阅读记录保存为文献下 **NoteIn** 中的可编辑 Zotero 笔记；多文献工作区的阅读记录保存在对应 collection。完整会话文字、章节和结果编号等元数据通过专用会话笔记保存，长会话分段存储。NoteOut 的 Markdown 正文也作为 Zotero 原生笔记保存。

启用 Zotero 数据同步后，另一台安装了 AbstractIn 的电脑可以从同步笔记恢复章节分组和完整讨论。新电脑会从完整的同步聊天笔记恢复阅读类型、标题和目标，无需重复初始化；PDF 仍需在本地可用。已有本地缓存也会检查同步来的新问答和摘要，打开 Chats 时会补入稍后同步到达的讨论。跨电脑继续讨论时会保留来源记录，避免直接覆盖另一台电脑的会话。

如果出现 **Could not read this item**，点击 **Restore reading** 重新加载当前文献的阅读状态与讨论。损坏的讨论索引会先备份，再从本地聊天和 Zotero 同步笔记重建；原笔记、聊天文件和会话不会被删除。

同步范围需要区分：

| 数据 | 保存与同步方式 |
|---|---|
| 阅读笔记、完整阅读会话及元数据 | 单篇文献下或工作区 collection 中的 Zotero 笔记；随数据同步。 |
| NoteOut 正文及文献关联 | Zotero 原生笔记及链接；随数据同步。 |
| 每份 NoteOut 的讨论历史、布局和本机草稿 | 保留在本机；目前不随笔记正文同步。 |
| PDF 附件 | 由 Zotero 文件同步或本地附件可用性决定。 |
| 插件设置、助手登录与线程 ID、提取文本缓存、图片附件 | 保留在本机，不随会话笔记同步。 |

图片问题在另一台电脑上可能需要重新提供图片。笔记写入失败时，插件保留本地会话并提示保存问题；回答菜单中的 **Save as note** 可手动保存完整回答。

多设备同步有自动化测试覆盖，具体 Zotero 环境下的双机同步仍需实际验证。

## 阅读伴侣与设置

可选择 **狨猴、白鹡鸰、海鹦**，或 **None**。选择 None 后整个阅读伴侣行隐藏，留出更多讨论空间。

当前狨猴使用提供的视频生成的透明循环动图，静止时显示该视频的第一帧。开始界面持续播放，讨论界面仅在回答生成期间播放，其余时候保持静止；系统的减少动态效果设置会关闭动画。

设置中可以调整配色、字体、字号、间距、按钮文字、回答语言，以及发送快捷键、自动滚动、过程显示和快捷问题。回答语言可以跟随提问语言，也可以指定。

## AI 助手、API 与模型选择

### 模型菜单

输入框底部的模型菜单按 **Agent / API → 模型** 分级。悬停或点击展开模型，不会因浏览而切换助手；选定模型后才应用。一级列表不再重复堆放配置项，统一从 **Setup → 对应助手或 API** 配置，保留键盘方向键、返回和 Escape 关闭。窄面板使用整宽子菜单。

Codex、Claude Code 可用 **Refresh … models** 读取本地 CLI 返回的目录；ACP 助手按其实际报告的能力提供模型。API 配置保存后会查询服务的模型列表，并显示 **Available models**，可用 **Refresh models** 刷新，发现失败时仍可填写模型 ID。列表展示不代表账号一定具备调用权限。

### 添加本地 CLI

设置 → Assistants 的 **Add agent (CLI)** 支持内置 Codex、Claude Code、Gemini CLI、Antigravity，以及自定义 **ACP v1、AbstractIn JSONL 或非交互纯文字 stdin/stdout** 调用。Gemini CLI 已有 `gemini --acp` 预设。CLI 需先在本机安装并完成相应服务的登录；只有命令名、但没有兼容调用协议的交互式程序，不能保证直接接入。

引导可填写或选择可执行文件，也可提供目录并在其中递归查找。Windows 下留空以 `C:\` 为搜索根，优先检查 PATH、npm、WinGet、scoop、编辑器扩展和常见安装目录，再搜索其余可访问目录，跳过系统目录；找到后保存实际执行路径，日常调用直接复用。搜索可取消，超时会提示缩小范围，失败不会覆盖已有路径。

四步引导为：**查找 CLI → 完成登录 → 检查连接与阅读能力 → 选择模型并 Enable**。检查使用样例材料，可能消耗服务额度；取消或失败不会启用新助手。图片、流式输出、模型选择、会话续接与原文访问按实际协议及检查结果开放。纯文字 CLI 在命令结束后返回答案；自定义助手通过有限检查不等于保证每项任务都能成功。

### 添加 API，包括学校或机构服务

**Add API** 可配置名称、服务地址、认证、模型和请求参数，支持 **OpenAI-compatible Chat Completions、Anthropic Messages、Gemini GenerateContent、Custom JSON**，提供 **GWDG SAIA、DeepSeek** 预设。学校提供的地址、密钥和模型由用户填写，不需要安装 CLI。自定义请求路径、额外请求头和响应字段等配置见 [助手适配说明](docs/agent-adapters.md)。

API 密钥与额外请求头保存在 **Zotero 登录管理器**，不写入聊天记录。保存配置或刷新模型不自动切换当前助手，检查后点击 **Enable** 才启用。API 与纯文字 CLI 可由插件检索并提供原文片段，无需模型自行读取本地文件；图片输入需要服务和模型支持并明确配置。

DeepSeek 原有连接仍可通过 **Setup → DeepSeek API**，或设置中的 **Guided setup** 配置、测试和更换密钥；这条内置连接只支持文字及插件提供的原文片段。API 调用可能产生费用。

当前功能说明对应 **v0.2.154**；最新安装包以 Release 为准。原始 Zusia 使用不同的插件 ID；其用户需要先手动安装一次 AbstractIn，之后再通过本项目更新。

## 数据与隐私

支持放在 Dropbox 等用户自建文件夹中的 PDF 链接附件，包括 Zotero“链接附件基础目录”的相对路径。原文件与附件链接保持不变。直接文件读取失败时，可从 Zotero 中已打开的同一附件读取原文快照；该快照不代表云端最新版本。若文件尚未下载到本机且 Zotero 也未加载内容，需要先使文件在本机可用。工作目录写入失败会单独报告目录位置。

AbstractIn 的本地工作区位于 Zotero 数据目录中的 `abstractin/`，包含会话缓存、文档副本、提取文本、图片和阅读状态。插件读取副本和缓存，原始 PDF 附件不被改写。

问题、所提供的文档上下文和图片，以及助手读取的原文内容，会通过所选助手发送到对应模型服务。使用本地 CLI 不意味着文档内容始终留在本机。Zotero 笔记在开启数据同步时也会上传到你的 Zotero 同步服务。

插件诊断日志位于 `<Zotero 数据目录>/abstractin/debug.log`，可能含有问题或上下文片段，分享前应检查内容。

## 当前边界

- 没有内置 OCR；扫描版或无法提取文本的 PDF 可能需要提供页面图片或选中文本。
- 原文定位依赖可读取的页面、目录和提取文本；无法核对的位置不会生成猜测链接。
- 本地助手需要单独安装、登录，并具备相应模型权限；插件模型列表不代表账号一定能调用全部模型。
- NoteOut 表格单元格内的公式暂未支持；TikZJax 支持随包提供的 TeX 资源，并非完整桌面 LaTeX 环境。
- 工作区来源目前不能跨书库；笔记讨论历史尚未跨设备同步。
- 当前为桌面 Zotero 插件，尚无 iPad 版本；QMD/HTML 阅读报告导出暂未提供。

## 开发与验证

```sh
npm ci
npm run build        # 输出项目根目录的 abstractin.xpi
npm test             # 自动化测试
npm run source:path  # 查看本地源码目录的绝对路径
```

原生界面验证可按环境选择：

```sh
npm run shots        # 需要 Firefox，生成界面截图
npm run test:zotero  # Linux Zotero 集成验证，需要对应环境
ZOTERO_BIN=/path/to/zotero bash test/integration/composer.sh  # 输入与公式；使用独立空库
ZOTERO_BIN=/path/to/zotero bash test/integration/appearance.sh
ZOTERO_BIN=/path/to/zotero bash test/integration/restart.sh
```

自动化测试覆盖阅读流程、会话、引用、源文定位、设置、渲染和适配器等逻辑；不能替代真实 Zotero 的界面、动画、模型访问和双机同步检查。Windows 安装及诊断参考 [Windows 使用说明](docs/WINDOWS-TESTING.md)，其中历史版本的验证条目供排查旧问题使用，当前界面以本 README 为准。

发布时保持 `package.json`、`package-lock.json` 和 `src/manifest.json` 的版本一致。仓库配置了标签触发的 Release 工作流，构建 XPI 和更新清单；实际手动发布时也必须同时上传两个文件：

```sh
npm run build
node scripts/updates.mjs
```

正式发布的版本需要高于已安装版本，Zotero 才能提供更新。仅推送文档或代码到 `main` 不会使现有插件自动升级。
