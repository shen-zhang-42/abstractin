# 三种回答模式设计

本文件记录已实现的三种回答模式及其边界。

| 界面名称 | 中文含义 | 原文查找 | 知识与回答边界 |
|---|---|---|---|
| Context only | 仅凭上下文 | 不读取或搜索 PDF | 解释用户提供的段落、图片和明确引用的会话内容。缺少材料时请用户提供，不用外部事实填补缺口。 |
| Balanced | 平衡模式 | 按问题需要查找 | 通用知识问题直接回答；书中特定陈述、证明、符号或作者做法需要证据时先查 PDF。 |
| Source only | 仅依据原文 | 围绕问题查找 PDF | 原文及用户提供的原文片段是事实依据，可以解释和推导，但不以外部知识补写书中没有的内容。 |

默认使用 Balanced。菜单中提供名称、图标和说明。

## 图标

Balanced 使用单色线条天平，表示在知识回答与原文证据之间按需要选择，文件为 `src/content/icons/reading-balanced.svg`。24 × 24 画布，1.8px 线宽，颜色跟随界面。天平保持水平，不显示加载或成功状态。

Context only 使用对话气泡；Source only 使用现有的文件查找图标。三种模式分别表达提供的上下文、按需判断、原文依据。

## Balanced 查证规则

1. 通用概念、一般数学解释和已充分提供的材料可以直接回答。
2. 问题涉及“这本书/这个定理/这个证明/当前页”且缺少相关陈述时，先尝试查证，不能仅因为输入片段不完整就要求用户粘贴。
3. 明确要求看原文时直接查证。后续问题应保留前一轮的定理或页码线索。
4. 查找按当前 Zotero 页、前后各四页、当前章节、整本文档逐步扩大；优先定位正文陈述与证明，而不是引用它的句子。
5. 已查到的原文用于回答书中特定问题；补充知识应与作者原文区分。
6. 查找确实失败时说明尝试的范围和缺失内容，再请用户提供片段；不能说“书上没有”，除非查证范围支持该结论。
7. 用户明确禁止查询时，本轮遵守禁止；需要原文的问题说明当前证据不足。

## 与现有实现的关系

旧 Knowledge discussion 选择映射到 Balanced，Source verification 映射到 Source only。未设置偏好时默认 Balanced。

实现将用户选择的 `answerMode` 与本轮实际取证的 `evidenceMode` 分开。自动查证不会改变模式偏好；切换模式时不复用旧模式的助手线程。Context only 跳过 PDF、注释与保存笔记的导出。Source only 在系统提示和本轮提示中均限制外部事实。

Balanced 对短定理选择、明确查原文请求优先取证；其余问题先判断已有上下文。缺失证据标记、要求粘贴原文或无法访问 PDF 的回答会触发一次自动查证，初步拒绝不会进入已保存对话。初始化文档结构仍走原文流程。
